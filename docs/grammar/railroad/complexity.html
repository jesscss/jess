jess grammar complexity

Measured from the same spec model the railroad pages are drawn from, so these numbers and those diagrams cannot disagree. Regenerate with node scripts/analyze-grammar-complexity.mjs.

The rendering is deliberately not optimised

Nothing here smooths, collapses or prettifies a diagram. Every rule the grammar defines is emitted, trivia rules included, in declaration order, and a monster rule is left looking like a monster. The only rendering option used is readable names for common terminals (IDENT instead of a 200-character character class), which changes how faithfully you can read the shape, not what the shape is. The one exception is forced: three rules must be pinned as opaque terminals or the emitter does not terminate at all — see the index.

How a symbol is counted

Symbols are the boxes a reader sees: one per terminal, one per non-terminal reference, one per annotation. One word of a keywords([…]) list is one box, so a 148-word list counts 148. Sequence, alternation, repetition and optionality are drawn as lines, loops and bypasses rather than boxes, so they count zero. +ops adds one for each repetition or bypass (*, +, ?, sepBy) a reader has to trace. References are not expanded — a reference counts one however big the rule it names.

How a row is counted

Rows are the alternatives stacked vertically in a rule's own diagram — the thing that makes you scan down rather than across. One row for the rule, plus (arms − 1) for every alternation, plus one for every bypass line (?, *, a sepBy that admits zero items). A straight sequence is 1 row; a twelve-arm alternation is 12.

A named reference is one row, however big the rule it names. That is the whole point of the metric, and it is a property of the model rather than a setting: buildSpecModel emits a reference as a leaf and gives the referenced rule its own production. There is no reference-expansion option to turn off. So a high row count means the grammar spelled those alternatives out inline instead of naming them.

How a chain is counted

Chains are distinct routes from entry to exit of this diagram: a sequence multiplies its children, an alternation sums them, an optional or a repetition adds one bypass path. Two truncations keep the number finite and re-derivable — a loop counts as one path rather than one per iteration count, and a reference is not expanded. Products still explode; anything at or over 1,000,000 is reported as unbounded rather than as a precise fiction.

The three lines

>30 symbols — too wide. >10 rows — too deep; alternatives that want names. Chains — branchiness, reported rather than thresholded. They fail differently and a rule can be bad at exactly one; the rules over the line on two of them are the ones worth naming loudest. Being under every line is not a certificate: depth, loop count, and the emitter can each ruin a small rule.
