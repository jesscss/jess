**Selector capture** turns a selector into a **value** — a first-class piece of data
you can store in a variable, pass to a function, or build selectors from — instead of
live selector syntax attached to a rule.

<AudienceGate include={['less']}>

Write it with `selector( … )` in value position. Its argument is a selector list, the
same one `:is()` takes:

```less
@card:  selector(.card);
@both:  selector(.card, .panel);   // a selector list is fine
```

</AudienceGate>

<AudienceGate include={['jess']}>

Write it with `selector( … )` in value position (no `$` sigil). Its argument is a
selector list, the same one `:is()` takes:

```less
$card: selector(.card);
$both: selector(.card, .panel);    // a selector list is fine
```

</AudienceGate>

<AudienceGate include={['sass']}>

Sass has no selector-capture syntax of its own. In `.scss`, `&` in a value is the
parent selector, as in Sass (`.a, .b { .c { x: &; } }` gives `x: .a .c, .b .c`).

Sass reads a selector string with `selector.parse()` from the `sass:selector` module (or the
deprecated global `selector-parse()`). The result is the same value `&` is: a comma list of
selectors, each a space list of its compound selectors and combinators.

```scss
@use 'sass:selector';
@use 'sass:list';

$both: selector.parse('.card, .panel');

#{$both} { padding: 1rem; }               // .card, .panel { padding: 1rem; }
.debug { count: list.length($both); }     // count: 2
```

The string can come from a variable or a mixin argument. A string that is not a selector
list, or that holds `&`, follows `functionMode` like any function that cannot compute: by
default the call is written out as authored, and with `functionMode: 'error'` the compile
stops with Dart Sass's message (Dart Sass always stops). The other `sass:selector`
functions (`append`, `nest`, `extend`, `replace`, `unify`, `is-superselector`,
`simple-selectors`) are not supported yet.

</AudienceGate>

## Why `selector()`

CSS already has a `selector()` function, and it already means "this argument is a
selector": `@supports selector(:has(a))` tests whether the browser supports a selector,
and so does `supports(selector(…))` inside CSS `if()`. Selector capture reuses that name
instead of inventing new syntax, so there is no special sigil to learn and nothing a
CSS parser doesn't already recognise.

Jess extends it in two ways:

- **In an ordinary value it captures.** CSS only uses `selector()` inside a support
  condition, where it is a test. Anywhere else in a value, Jess reads it as a captured
  selector you can keep.
- **It takes a selector list.** CSS's `selector()` takes a single complex selector.
  Jess accepts a comma-separated list, the same argument `:is()` and `:where()` take,
  so `selector(.card, .panel)` is one value holding both selectors.

Inside a support condition nothing changes: `@supports selector(.a > .b)` and
`if(supports(selector(.a)): …)` are still CSS's feature test, in every syntax.

## What it's for

Once a selector is a value you can:

- **Reuse it** — store a selector once and use it as a selector in several places
  (see below).
- **Pass it around** — hand it to a mixin, or compare it in a guard
  (`when (@s = selector(.a))`).
- **Take it apart** — it is a list with one item per selector (see below).

Selector functions that build new selectors from a captured one (append, nest, unify,
replace) are not available yet.

## A selector list value

The captured value is the same value `&` is in a `.jess` or `.scss` value, and the
same value Sass's `selector.parse()` returns: a comma list with one item per
selector, each item a space list of its compound selectors and combinators. So
`selector(.card, .panel > h2)` has two items, and its second is `.panel`, `>`, `h2`.

<AudienceGate include={['less']}>

```less
@cards: selector(.card, .panel > h2);

.debug {
  count: length(@cards);       // count: 2
  second: extract(@cards, 2);  // second: .panel > h2
  all: @cards;                 // all: .card, .panel > h2
}

each(@cards, {
  @{value} { padding: 1rem; } // one rule per selector
});
```

</AudienceGate>

<AudienceGate include={['jess']}>

```less
@-use "#sass/list";

$cards: selector(.card, .panel > h2);

.debug {
  count: $list.length($cards);     // count: 2
  second: $list.nth($cards, 2);    // second: .panel > h2
  all: $cards;                     // all: .card, .panel > h2
}

$for ($card of $cards) {
  ${card} { padding: 1rem; }       // one rule per selector
}
```

</AudienceGate>

<AudienceGate include={['sass']}>

When a `.scss` file is converted to `.jess`, `selector.parse('.card, .panel')` with a
plain string becomes `selector(.card, .panel)`, and any other argument keeps the call
through the module (`$selector.parse($cards)`).

</AudienceGate>

Written in a plain value, it is the selector list, `.card, .panel > h2`, as `&` is.

## Using a captured selector in another selector

Interpolate the variable where a selector goes. Every captured branch is used, and
the nesting works as if you had written the list there:

<AudienceGate include={['less']}>

```less
@cards: selector(.card, .panel);

.page {
  @{cards} {
    padding: 1rem;
  }
}
```

</AudienceGate>

<AudienceGate include={['jess']}>

```less
$cards: selector(.card, .panel);

.page {
  ${cards} {
    padding: 1rem;
  }
}
```

</AudienceGate>

With nested output (the default) that writes the branches under `.page`:

```css
.page {
  .card,
  .panel {
    padding: 1rem;
  }
}
```

With `collapseNesting` the same source writes `.page :is(.card, .panel) { padding: 1rem; }`.

A `&` inside the capture stays a parent reference, resolved where the selector is
used: `selector(&.active, & + .item)` interpolated inside `.tab` refers to `.tab`.

## Gluing a captured selector to other text

A captured selector interpolated next to other selector text is placed the way `&` is.
The same rule covers `&` itself used as a value, and the result of `selector.parse()`:

- **A name glued after it** builds a name from each selector, as `&__title` does:
  one rule per selector.
- **Anything else glued to it** (a class before it, a pseudo-class after it) treats the
  list as one unit, `:is(…)`, as `&` stands for its parent.

<AudienceGate include={['less']}>

```less
@cards: selector(.card, .panel);

@{cards}__title { font-weight: bold; }
.theme-dark@{cards} { color: white; }
@{cards}:hover { outline: none; }
```

</AudienceGate>

<AudienceGate include={['jess']}>

```less
$cards: selector(.card, .panel);

${cards}__title { font-weight: bold; }
.theme-dark${cards} { color: white; }
${cards}:hover { outline: none; }
```

</AudienceGate>

<AudienceGate include={['sass']}>

```scss
.card, .panel {
  #{&}__title { font-weight: bold; }
  .theme-dark#{&} { color: white; }
}
```

Dart Sass pastes the text of `&` here and re-reads it (`.card .card, .card .panel__title, …`).
Jess places it as `&` is instead.

</AudienceGate>

```css
.card__title,
.panel__title {
  font-weight: bold;
}
.theme-dark:is(.card, .panel) {
  color: white;
}
:is(.card, .panel):hover {
  outline: none;
}
```

<AudienceGate include={['sass']}>

In `.scss` the rules above stay nested under `.card, .panel`, as any nested rule does.

</AudienceGate>

A plain comma list is different: it holds text, not selectors, so wherever it is glued
each item is pasted in and the rule repeats for it.

<AudienceGate include={['less']}>

```less
@fruits: apple, satsuma;            // a plain list
@fruit-selectors: selector(apple, satsuma);

.fruit-@{fruits} { color: orange; }          // .fruit-apple, .fruit-satsuma
.fruit-@{fruit-selectors} { color: orange; } // .fruit-:is(apple, satsuma)
```

</AudienceGate>

<AudienceGate include={['jess']}>

```less
$fruits: apple, satsuma;            // a plain list
$fruit-selectors: selector(apple, satsuma);

.fruit-${fruits} { color: orange; }          // .fruit-apple, .fruit-satsuma
.fruit-${fruit-selectors} { color: orange; } // .fruit-:is(apple, satsuma)
```

</AudienceGate>

The second rule matches an element with the class `fruit-` that is also an `apple` or a
`satsuma` element: the class before a captured selector never becomes part of a name,
just as `.fruit-&` does not.

<AudienceGate include={['less', 'jess']}>

An argument that is not a selector list (`selector(1px)`, `selector()`) is an error
at the argument. The rest of the stylesheet still parses, so an editor shows every
such error at once.

</AudienceGate>
