**Selector capture** turns a selector into a **value** — a first-class piece of data
you can store in a variable, pass to a function, or build selectors from — instead of
live selector syntax attached to a rule.

<AudienceGate include={['less']}>

Write it with `selector( … )` in value position. Its argument is a selector list, the
same one `:is()` takes:

```less
@card:  selector(.card);
@both:  selector(.card, .panel);   // a selector list is fine
```

</AudienceGate>

<AudienceGate include={['jess']}>

Write it with `selector( … )` in value position (no `$` sigil — it serializes back as
`selector(…)`). Its argument is a selector list, the same one `:is()` takes:

```less
$card: selector(.card);
$both: selector(.card, .panel);    // a selector list is fine
```

</AudienceGate>

<AudienceGate include={['sass']}>

Sass reads a selector string with `selector.parse()` from the `sass:selector` module (or the
deprecated global `selector-parse()`). The result is the same value `&` is: a comma list of
selectors, each a space list of its compound selectors and combinators.

```scss
@use 'sass:selector';
@use 'sass:list';

$both: selector.parse('.card, .panel');

#{$both} { padding: 1rem; }               // .card, .panel { padding: 1rem; }
.debug { count: list.length($both); }     // count: 2
```

The string can come from a variable or a mixin argument. Through the module, a string that is
not a selector list, or that holds `&`, is an error that stops the compile, as in Dart Sass;
the global `selector-parse()` follows `functionMode`, so by default such a call is written out
as authored. The other `sass:selector` functions (`append`, `nest`, `extend`, `replace`,
`unify`, `is-superselector`, `simple-selectors`) are not supported yet.

</AudienceGate>

## What it's for

Once a selector is a value you can:

- **Reuse it** — store a selector once and reference it in several places.
- **Operate on it** — pass it to selector-aware functions (append, nest, unify,
  replace…) that build new selectors from existing ones.
- **Compute selectors** — assemble a selector from parts and apply the result.

The captured value round-trips — `selector(.card, .panel)` serializes back to
`selector(.card, .panel)` — and behaves the same wherever a selector value is expected. The
concept is identical across syntaxes; only the spelling differs.

`selector()` captures only in an ordinary value. Inside a support condition it is still
CSS's feature test — `@supports selector(.a > .b)` and `if(supports(selector(.a)): …)`
test whether the browser supports the selector — and in plain CSS and SCSS a
value-position `selector()` is an ordinary function call.

<AudienceGate include={['less', 'jess']}>

An argument that is not a selector list (`selector(1px)`, `selector()`) is an error
at the argument. The rest of the stylesheet still parses, so an editor shows every
such error at once.

</AudienceGate>
