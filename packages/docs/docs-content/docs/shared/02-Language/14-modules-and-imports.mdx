This page is the source of truth for stylesheet and script modules in Jess and
Less 5. The two module families have different jobs and different support
status:

| Module family | Jess | Less 5 | Current status |
| --- | --- | --- | --- |
| Stylesheets | `@-compose` | `@compose` | Available |
| Scripts and data | `@-use` / `@-from` | `@use` / `@from`, with dashed aliases | Planned; do not use yet |

The compose family loads stylesheet code, exposes that stylesheet's own public
members, and may emit CSS. `@use` and `@from` are reserved for JavaScript,
TypeScript, JSON, and built-in function modules. They do not replace one another.

# Stylesheet modules in Less 5

Use `@compose` for a stylesheet dependency with isolated scope.

```less title="theme.less"
@primary: #3366ff;
@spacing: {
  compact: 4px;
  normal: 8px;
}

.theme-base {
  color: @primary;
}
```

```less title="app.less"
@compose "./theme.less";

.button {
  color: @theme.primary;
  padding: @theme.spacing.normal;
}
```

The default namespace comes from the file name. Set it explicitly with
`as name`, or use `as *` to merge the module's own members into the current
scope:

```less
@compose "./theme.less" as brand;
.button { color: @brand.primary; }

@compose "./layout.less" as *;
.card { gap: @card-gap; }
```

Prefer a namespace. `as *` is convenient for migration, but makes the source of
a name harder to see.

## Isolated, non-transitive scope

A composed module cannot read variables from its importer. Its own composed or
imported dependencies also stay private: composing `library.less` does not give
the caller direct access to members from `library.less`'s dependencies.

This differs from legacy `@import`, which folds a source file into the current
scope and lets names leak through the import graph.

## Configuration with `with` and `set`

Both forms pass variable values into a module:

```less
@compose "./theme.less" with {
  @primary: rebeccapurple;
}
```

- `with` configures one compose edge. A later compose starts from the module's
  defaults, and each configured edge emits its own CSS.
- `set` establishes one shared configuration for that resolved module during
  the compilation. Later plain composes reuse it. Repeating the same `set` is
  allowed; a conflicting `set` is an error.
- A plain compose, or a module using shared `set` configuration, emits that
  module's CSS once. Two separate `with` configurations each emit their result.

Less variables are configurable declarations, so a module can use an ordinary
declaration as its default:

```less title="theme.less"
@primary: blue;
.theme { color: @primary; }
```

## `@import` remains a legacy bridge

`@import` keeps Less 4 behavior: extensions and options decide whether it emits
a CSS import or folds source into the current scope. `@-import` is the explicit
source-fold form. Both continue to work for migration, but warn in Less 5 because
their shared scope is harder to reason about.

```less
@import "./legacy.less";   // legacy heuristic import
@-import "./legacy.less";  // legacy source fold
@compose "./theme.less";   // isolated stylesheet module
```

For a bare `@import`, `.css` targets stay in the output, other extensions are
compiled as Less, and a path with no extension gets `.less` appended. Prefer a
leading `./` for a local file so the intent is distinct from a package
specifier.

Legacy import options keep their Less 4 meanings:

| Option | Effect |
| --- | --- |
| `reference` | Load the file but emit rules only when referenced by a mixin or `:extend`. |
| `inline` | Include the source verbatim without processing it. |
| `less` / `css` | Force Less compilation or CSS passthrough. |
| `once` / `multiple` | Import once, or allow repeated imports. |
| `optional` | Continue when the target is missing. |

Options can be combined: `@import (optional, reference) "./foo.less";`.

# Stylesheet modules in Jess

Jess spells compiler directives with a dash. Use `@-compose` for a stylesheet
dependency with isolated scope:

```less title="theme.jess"
$primary?: #3366ff;
$spacing: {
  compact: 4px;
  normal: 8px;
}

.theme-base {
  color: $primary;
}
```

```less title="app.jess"
@-compose "./theme.jess";

.button {
  color: $theme.primary;
  padding: $theme.spacing.normal;
}
```

The default namespace comes from the file name. `as name` selects another
namespace, and `as *` exposes the module's own members without a namespace.

```less
@-compose "./theme.jess" as brand;
.button { color: $brand.primary; }

@-compose "./layout.jess" as *;
.card { gap: $card-gap; }
```

Composed scope is isolated and non-transitive. A module cannot read the
importer's variables, and its dependencies do not become members of the
importer's namespace.

## Configuration with `with` and `set`

Jess uses the same two configuration lifetimes as Less 5:

```less
@-compose "./theme.jess" with {
  $primary: rebeccapurple;
}
```

- `with` configures one compose edge; each configured edge emits its own CSS.
- `set` establishes one shared configuration for the resolved module. Later
  plain composes reuse it, and a conflicting second `set` is an error.
- Plain and shared `set` modules emit once per compilation.

Only optional declarations are configuration knobs in Jess. Declare a default
with `?:`:

```less title="theme.jess"
$primary?: blue;
.theme { color: $primary; }
```

Trying to configure a hard `$primary:` declaration is an error.

## Forwarding and legacy imports

`@-export "./theme.jess"` forwards a stylesheet module's API to downstream
consumers. `@-import` is the legacy source-fold bridge; it warns because it uses
shared scope. A bare `@import` in a `.jess` file is always native CSS and passes
through to the output.

```less
@-export "./theme.jess";
@-import "./legacy.jess";
@import "./browser.css";
```

# Sass module syntax in the Jess compiler

When compiling SCSS, stylesheet `@use` lowers to the same isolated stylesheet
module model. SCSS keeps its own syntax and singleton configuration behavior:

```scss
@use "./theme.scss" as theme with (
  $primary: rebeccapurple
);

.button { color: theme.$primary; }
```

A Sass configuration variable must be declared with `!default`. The configured
module emits once, and a conflicting later configuration is an error.

When translating SCSS to Jess source, use `@-compose` for stylesheet modules:

| SCSS | Jess |
| --- | --- |
| `@use "./theme";` | `@-compose "./theme";` |
| `@use "./theme" as t;` | `@-compose "./theme" as t;` |
| `@use "./theme" with ($x: 1);` | `@-compose "./theme" with { $x: 1; }` |
| `@forward "./theme";` | `@-export "./theme";` |

</AudienceGate>

## Script and data modules: reserved, not executable yet

The script-module syntax is reserved for a later release:

<AudienceGate include={['jess']}>

```less
// Planned syntax; these directives are not executable yet.
@-use "./tokens.json" as tokens;
@-from "./functions.js" import (double);
```

Jess currently parses `@-use` and `@-from` into module import nodes, but the
evaluator does not consume those nodes or bind their exports. They round-trip to
CSS, and references that depend on the import remain unresolved. The compiler's
module loader and sandbox runtime exist, but this import-to-binding connection
has not shipped.

</AudienceGate>

<AudienceGate include={['less']}>

```less
// Planned syntax; Less 5 does not recognize or execute this as a module yet.
@use "./tokens.json" as tokens;
@from "./functions.js" import (double);
```

Less 5 does not currently recognize these as script-module directives. Continue
to use preloaded plugins or the deprecated `@plugin` bridge when JavaScript
integration is unavoidable. Inline backtick JavaScript remains removed.

</AudienceGate>

JSON will be a data-only import. Local or package JavaScript and TypeScript will
require the opt-in `@jesscss/plugin-js` runtime and its Deno sandbox policy. The
syntax above should be treated as a preview until this page marks it available.

## Native CSS imports

A native CSS `@import` targets a URL or CSS file and stays in the emitted CSS so
the browser can fetch it:

```css
@import url("https://fonts.example/css?family=Inter");
@import "reset.css";
```

In Jess, every bare `@import` is native CSS. In Less, the existing extension and
option rules still decide whether a bare import is native CSS or a legacy source
fold.
