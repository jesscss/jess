Jess supports expressions, which are used to evaluate values, perform calculations, and more.

In Jess, an `Expression` is always written as `$(`...`)`.

- `$var` is a variable `Reference` (not an `Expression`).
- `$(...)` is an `Expression`.

If you need to evaluate a variable inside an expression, use `$($var)`.

## Examples

### Basic arithmetic

```less
value: $(1 + 2); // 3
value: $(1 - 2); // -1
value: $(1 * 2); // 2
value: $(1 / 2); // 0.5
value: $(1 % 2); // 1 (modulus)
```

### CSS values

```less
value: $(#222 / 2); // #111
```

### Jess variables

```less
$width: 10px;
$height: $($width + 10px);

#header {
  width: $width;
  height: $height;
}
```

## References vs expressions

Inside an expression, plain identifiers are treated as normal values/keywords when possible.

```less
$color: red;
value: $(red); // red (color keyword literal)
value: $($color); // red (variable reference inside Expression)
value: $less.iscolor($color); // true
```

```less
$num: 10;
value: $($num + 1); // 11
```

## Current public contract

Use the wrapper for arithmetic. Unwrapped arithmetic such as `$w + 1` is not part
of the public language contract; write `$($w + 1)`.

Reference-chain arithmetic such as `$(.w + 1)` is also not public syntax yet.
Resolve the reference first, or keep the operation around a supported variable
reference.

String concatenation with `+`, comparison expressions as output values, and
optional `?` / `??` operators are not documented as supported until they have
parser and evaluator tests.
