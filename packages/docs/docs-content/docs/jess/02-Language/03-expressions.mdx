Expressions let Jess evaluate values explicitly.

Write an expression as `$(`...`)`.

- `$var` is a variable `Reference` (not an `Expression`).
- `$(...)` is an `Expression`.

Inside an expression, keep variable references explicit: `$($var)`.

## Examples

### Basic arithmetic

```less
value: $(1 + 2); // 3
value: $(1 - 2); // -1
value: $(1 * 2); // 2
value: $(1 / 2); // 0.5
value: $(1 % 2); // 1 (modulus)
```

### CSS values

```less
value: $(#222 / 2); // #111
```

### Jess variables

```less
$width: 10px;
$height: $($width + 10px);

#header {
  width: $width;
  height: $height;
}
```

## References vs expressions

Inside an expression, a plain identifier is a value or keyword. A variable still
uses its `$` sigil.

```less
$color: red;
value: $(red); // red (color keyword literal)
value: $($color); // red (variable reference inside Expression)
value: $less.iscolor($color); // true
```

```less
$num: 10;
value: $($num + 1); // 11
```

## Arithmetic is explicit

Keep arithmetic inside the expression wrapper:

```less
$w: 10px;
width: $($w + 1px);
```

Use a variable reference inside the expression. Do not write unwrapped arithmetic
such as `$w + 1px`.

## Units

An expression computes with units. A unitless number added to or subtracted
from a dimension takes the dimension's unit, multiplying or dividing by one
keeps the unit, compatible units convert, and like units cancel:

```less
value: $(1 + 2px);         // 3px
value: $(2px * 3);         // 6px
value: $(1cm + 10mm);      // 2cm
value: $(2px / 1px);       // 2
value: $(1px * 1px / 1px); // 1px
```

Mixing units that do not convert is an error by default: `$(1px + 3em)` stops
the compile with `eval/invalid-unit-arithmetic` at the operation that mixed
them. So does a result whose unit CSS cannot express — an area such as
`$(1px * 2px)` or a reciprocal such as `$(1 / 2px)`. Write `calc(1px + 3em)`
when the browser should resolve it.

The rule follows the expression wherever its value is used:
`calc(100% - $(1px + 3em))` is the same error, because the math belongs to the
`$( … )`, not to the `calc()` around it.

The `unitMode` compile option changes that default, exactly as it does for
Less: `preserve` keeps the math as `calc(1px + 3em)` and warns
(`eval/unexpressible-unit`), and `loose` computes Less 4.x's answer
(`$(1px + 3em)` is `4px`). Without the option, `.jess` uses `strict`. A
unitless number takes the other operand's unit under every setting.
