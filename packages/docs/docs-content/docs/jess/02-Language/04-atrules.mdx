Jess compiler at-rules use a dash prefix so bare CSS at-rules remain available
to the platform.

| At-rule | Purpose | Status |
| --- | --- | --- |
| `@-compose` | Load an isolated stylesheet module | Available |
| `@-export` | Forward a stylesheet module API | Available |
| `@-import` | Fold a stylesheet into shared scope | Available, discouraged |
| `@-use` | Load a script or data module namespace | Syntax preview |
| `@-from` | Import selected script or data exports | Syntax preview |

The complete module contract and current support status live on
[Modules & imports](/docs/language/modules-and-imports). That shared page is the
source of truth for both Jess and Less 5.

## `@-compose`

`@-compose` loads a stylesheet in isolated scope, emits its CSS, and exposes
the module's own top-level members through a namespace.

```less
@-compose "./theme.jess";

.box {
  color: $theme.primary-color;
}
```

The default namespace comes from the file name. Select one with `as name`, or
use `as *` to expose the module's own members without a namespace:

```less
@-compose "./theme.jess" as brand;
.box { color: $brand.primary-color; }

@-compose "./mixins.jess" as *;
.card { $ > card(); }
```

A module cannot read bindings from its importer. Its own dependencies remain
private, so the caller cannot reach through the namespace into a grandchild
module.

### `with` and `set`

Both clauses pass values into optional module declarations:

```less title="theme.jess"
$primary-color?: blue;
.theme { color: $primary-color; }
```

```less
@-compose "./theme.jess" with {
  $primary-color: rebeccapurple;
}
```

- `with` applies to one compose edge. Each separately configured edge emits
  its own result.
- `set` establishes shared configuration for the resolved module. Later plain
  composes reuse it, and a conflicting second `set` is an error.
- Plain and shared `set` modules emit once per compilation.

Only declarations written with `?:` are configurable. A hard `$name:`
declaration rejects configuration.

## `@-export`

`@-export` forwards a stylesheet module API to downstream consumers:

```less
@-export "./theme.jess";
```

## `@-use` and `@-from`

These spellings are reserved for JavaScript, TypeScript, JSON, and built-in
function modules:

```less
// Syntax preview; not executable in the current alpha.
@-use "./tokens.json" as tokens;
@-from "./functions.js" import (double as twice);
```

The parser creates structured module import nodes, but evaluation does not yet
bind exports from them. The directives currently round-trip to CSS. See
[Modules & imports](/docs/language/modules-and-imports#script-and-data-modules-reserved-not-executable-yet)
for the exact boundary.

## `@-import`

`@-import` is the legacy source-fold form. It evaluates the imported file in
shared scope and warns because names can leak in both directions. Use
`@-compose` for new stylesheet modules.

```less
@-import "./legacy.jess";
```

A bare `@import` in a Jess file is always native CSS and passes through to the
output:

```css
@import "./browser.css";
```
