:::caution Migration is manual today
There is **no `jess convert` command**. An automated `.less`/`.scss` → `.jess`
converter is planned but not implemented, and the `jess` CLI has no subcommands
at all — it compiles a single file to CSS (`jess input.less -o dist`).

You do not have to migrate to use Jess: the compiler reads `.less` and `.scss`
sources directly. Port files to `.jess` by hand, using the mappings below, only
where you want the native syntax.
:::

## Construct mapping

Each section pairs a source construct with the Jess spelling it becomes. These
are the same mappings an automated converter would apply, so they are equally
useful as a hand-migration checklist and as the specification for that future
tool.

### At-rules

At-rules become their prefixed counterparts. Import rules also have to
distinguish file-relative from module-relative paths, because Jess requires
file-relative imports to be explicit.

E.g. `@import` becomes `@-import`

<Tabs>
  <TabItem value="Less">
  ```less
  @import "variables"; // variables.less
  ```
  </TabItem>
  <TabItem value="Sass">
  ```less
  @import "variables"; // variables.scss
  ```
  </TabItem>
  <TabItem value="Jess">
  ```less
  @-import "./variables"; // variables.jess
  ```
  </TabItem>
</Tabs>

:::tip Prefer `@-compose` once ported
`@-import` is a **legacy bridge** — it works and eases a mechanical port, but it
emits a deprecation warning because it re-exports everything and changes the
evaluation context per call. The Jess module system is
[`@-compose`](/docs/Language/atrules) (namespaced, isolated scope). A Sass
`@use "./theme";` maps most cleanly to `@-compose "./theme";`, not `@-import`.
Use `@-import` for the first pass, then promote real modules to `@-compose`.

`@-compose` currently accepts a quoted path and an optional `as` alias
(`@-compose "./theme" as t;`). Sass's `@use ... with (...)` configuration has no
`@-compose` equivalent yet.
:::

### Variable declarations

Both Jess `$name: value` and `$$name: value` create or update both live and
scoped bindings. The reference sigil, rather than the declaration, selects
lookup behavior.

<Tabs>
  <TabItem value="Less">
  ```less
  @color: #06c;
  ```
  </TabItem>
  <TabItem value="Sass">
  ```less
  $color: #06c;
  ```
  </TabItem>
  <TabItem value="Jess">
  ```less
  $color: #06c;
  ```
  </TabItem>
</Tabs>

### Expressions

Jess expressions are always `$(`...`)`. Plain `$var` is a variable reference. Inside an expression, variables keep their `$` sigil — a bare identifier is a keyword, not a variable.

Use:

- `$var` for a direct variable reference
- `$($var)` when you need that reference inside an expression
- `$[ident]` for variable identifier interpolation (selector/property-name interpolation)
- `$['name']` for property lookup interpolation keys (e.g. Less `${name}`)

#### Less-to-Jess

<div style={{ display: 'flex', flexDirection: 'row', gap: '1rem' }}>
  <div style={{ flex: 1 }}>
  ```less
  value: @width + 1;
  value: (@width / 2);
  ```
  </div>
  <div style={{ flex: 1 }}>
  ```less
  value: $($$width + 1);
  value: $($$width / 2);
  ```
  </div>
</div>
