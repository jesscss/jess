:::danger This page describes a planned feature

Stylesheet-defined functions are **not implemented** in the 2.x alpha. Neither
the `@() > { result: … }` definition form nor the `$name()` call form is accepted
by the `.jess` parser today. This page is the design; none of the samples below
compile yet.

Working alternatives right now: [mixins](./mixins) for reusable rule bodies, and
the [built-in function set](/docs/Functions/about) for value computation.

:::

:::info

This section refers to functions defined in stylesheets. For importing functions from other languages, see [the `@-use` and `@-from` at-rules](./atrules#-use-and--from).

:::

In Jess, functions are anonymous mixins that return a single value. We indicate we want a single value with `>`, and the return value is then assigned with `result`. (This matches the CSS `@function` spec, where the return descriptor is `result:`.)

```less
// Define a function
$my-function: @() > {
  result: $(1 + 2);
}

// Call a function
value: $my-function(); // 3
```

Like arrow functions in JavaScript, anonymous functions can also return a single expression.

```less
$my-function: @() > $(1 + 2);

value: $my-function(); // 3
```

:::info[No early returns]

Functions do not have "early" returns — the **last** `result:` assignment wins. A `result:` inside an `$if` branch does not short-circuit; evaluation continues, and a later `result:` overrides it. For example:

```less
$my-function: @() > {
  $if(true) {
    result: one;
  }
  result: two;
}
// value is `two` — the last result: assignment wins
```

Think of functions like "mixins that look up the final assignment to a property named `result`".

:::
