Jess has three `$` sigil forms. Which one you reach for is decided by the
*position* you are writing in, not by what the value turns out to be:

| Form | Role | Where it goes | What goes inside |
| --- | --- | --- | --- |
| `${…}` | **interpolation** | name, selector, and string positions | a variable **name** |
| `$[…]` | **lookup** | value positions | a value expression — the key |
| `$(…)` | **expression** / grouping | value positions | an expression |

`${name}` means *the value of `$name`*, spliced in as text. Its body is a plain
name on purpose, so an interpolation position stays a splice point rather than
turning into a place to compute. (`${m[key]}` and `${m.key}` are a planned
extension; today the body is a name.)

`$[…]` is a **lookup**, and lookups always read a key from a receiver. `$m[key]`
reads `key` from `$m`; `$[key]` reads it from the surrounding scope, which is why
`$[$foo]` means "the variable *named by* `$foo`" — a double indirection, not a
plain splice. That is exactly why `${…}` exists: without it there was no way to
say "just put `$foo` here".

Bare interpolation is not an option: `-` is an identifier character, so in
`--$name-color` there is no unambiguous place for the name to end. The braces
are the boundary.

Jess also has explicit selector capture:

- `*[...]` stores a selector or selector list as a selector-valued variable.

In selector contexts, an interpolated value may still resolve to a non-identifier selector fragment at runtime.

## Quick guide: which form to use?

- **Selector/property/mixin names**: use `${ident}`
- **Selector-valued variables**: use `*[...]`
- **Strings and custom property values**: use `${ident}`
- **Normal values**: use direct references like `$var`; use `$(...)` when you need expression behavior
- **Reading a key out of a collection**: use `$m[key]` — see [Namespaces and maps](./10-namespaces-and-maps.mdx)

## Selector capture

Use `*[...]` when the value itself should stay a selector, not just text output.

```scss
$target: *[.notice, .warning];
```

This differs from normal interpolation:

- `$(...)` interpolates an expression into output.
- `*[...]` captures parsed selector syntax so selector-aware features can use it later.

## Interpolation examples

### 1. Selectors in style rules

```scss
$side: left;
.widget-${side} {
  float: $side;
}
```
→
```css
.widget-left {
  float: left;
}
```

### 2. Property names in declarations
```scss
$radius: top-right;
.card {
  border-${radius}-radius: 12px;
}
```
→
```css
.card {
  border-top-right-radius: 12px;
}
```

### 3. Custom property values
```less
$theme: dark;
body {
  --theme-mode: ${theme};
  --theme-mode-fallback: ${theme};
}

.card {
  border-color: rebeccapurple;
  box-shadow: 0 0 0 2px $['border-color'];
}
```
→
```css
body {
  --theme-mode: dark;
  --theme-mode-fallback: dark;
}

.card {
  border-color: rebeccapurple;
  box-shadow: 0 0 0 2px rebeccapurple;
}
```

:::info

Note: in normal property values, you can usually just use `$theme`. A custom property value is uninterpreted text, so a variable there has to be spliced explicitly with `${theme}`. `$['border-color']` is different again: it is a *lookup*, reading another declaration value out of scope — not a DOM-level custom property.

:::

### 4. $extend
```scss
$type: *[.notice];
.notice {
  color: orange;
}
.danger {
  $extend $type;
}
```
→
```css
.danger, .notice {
  color: orange;
}
```

### 5. Plain CSS @imports
```scss
$family: "modern";
@import url("fonts/${family}.css");
```
→
```css
@import url("fonts/modern.css");
```

### 6. Plain CSS function names

A function name sits inside a *value*, so it is reached with the lookup form
rather than `${…}`:

```scss
$fn: "min";
$s1: 30vw;
$s2: 50vw;
.container {
  width: $[fn]( $s1, $s2 );
}
```
→
```css
.container {
  width: min(30vw, 50vw);
}
```

### 7. Less and SCSS source conversion

```less
// Less input
.@{name} { color: red; }
```
```scss
// Jess output shape
.${name} { color: red; }
```

```scss
// SCSS input (single variable interpolation in selector/property name)
.btn-#{$name} { color: red; }
```
```scss
// Jess output shape
.btn-${name} { color: red; }
```

### 8. Any plain output

```scss
$color-name: "red";
.container {
  color: ~"${color-name}";
}
```
→
```css
.container {
  color: red;
}
```

## TL;DR
1. Use `${name}` for a dynamic selector, property, or mixin-name segment; use `$(…)` for a full expression in value position; use `$m[key]` (or `$[key]`) to read a key out of a collection.
2. Use `*[]` when the variable itself should hold a selector or selector list.
3. Don't wrap variables for no reason; use direct variables unless you need interpolation.
4. Never interpolate numbers if you want to do math with them.
5. Escape strings with `~""` for clarity when you want to drop quotes from a string.

Jess is designed to be simple and clear.
